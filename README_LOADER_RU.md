# Лоадер для Smite_Internal222

Это комплект файлов для добавления в **первый** проект, а не полный проект. Лоадер перенесён из второго архива и адаптирован под `Trainer.vcxproj`: он собирает `Trainer.dll` и кладёт копию в `dist` с номером сборки SDK в имени. Готового EXE в комплекте нет: его нужно собрать на Windows. Старую готовую DLL из второго проекта комплект не использует.

## Установка и первая сборка

1. Сделайте резервную копию первого проекта и пользовательской конфигурации. Распакуйте первый архив. Скопируйте **содержимое** этого комплекта в папку `Smite_Internal222`, рядом с `Trainer.vcxproj` и `Trainer.sln`. Сохраните структуру `tools` и `dist`. Если файлы уже существуют, сначала сохраните их отдельно; проверьте конфликт до замены.
2. Нужны Windows x64, Visual Studio 2022/Build Tools с MSBuild, C++ Desktop, MSVC v143 и Windows SDK; для сборки интерфейса — C#/.NET Framework build tools и .NET Framework 4.8 Targeting Pack. Компоненты устанавливаются отдельно через Visual Studio Installer. Лоадер не устанавливает их сам.
3. Запустите `Build_Loader.bat`. При успехе создаётся `dist\SmiteLoader.exe`.
4. Запустите `Build_Trainer_for_Loader.bat`. Он пересобирает `Trainer.vcxproj` в Release x64 и копирует результат в `dist\Smite_Internal_<сборка_SDK>.dll`. Если известное расхождение в генерации SDK обнаружено, скрипт добавит include в `CppSDK\SDK\Hemingway_parameters.hpp`. Поэтому резервная копия важна и для первой сборки.
5. Запустите игру обычным способом, дождитесь лобби и запустите `dist\SmiteLoader.exe`. Номер сборки игры и SDK должен совпадать. Нажмите **Inject trainer**. При ошибке откройте **Open log**. Права доступа к процессу могут потребовать запуска лоадера от администратора.

В приложенном первом проекте `CppSDK\SDK.hpp` указывает на сборку **1641548**. Это не подтверждает, что установленная игра сейчас той же версии. Не переименовывайте DLL для обхода проверки версии: совпадение имени не означает совместимость.

## Обновление после обновления игры

1. Закройте игру. Запустите `dist\SmiteLoader.exe` и нажмите **Launch update mode**. Укажите `Hemingway-Win64-Shipping.exe`, если автоматический поиск его не нашёл. Лоадер запускает EXE напрямую для обновления; это **не гарантирует офлайн-режим**, не отключает защиту и не проверяет её состояние.
2. В той же сессии лоадера нажмите **Inject Dumper-7**. Требуется `dist\Dumper-7.dll`, включённая в комплект из второго архива. Лоадер меняет `ExecuteSDKTestScript` в существующем локальном `Dumper-7.ini` рядом с EXE игры, а если его нет — в `C:\Dumper-7\Dumper-7.ini`. Это изменение не откатывается автоматически.
3. Дождитесь завершения генерации. Нажмите **Dumper finished · Build** и подтвердите. Лоадер ищет данные в `C:\Dumper-7`, проверяет номер сборки, маркеры и наличие нужных проекту SDK-файлов, затем заменяет `CppSDK` и запускает полную сборку Release x64.
4. При успехе предыдущий SDK остаётся в скрытой папке `.auto_sdk_backup_<id>` в корне проекта; её путь выводится в журнал. При ошибке после замены SDK скрипт пытается вернуть старый SDK. Если откат прервался, сохраните обе папки и проверьте журнал вручную. Сборка и другие её артефакты могут меняться, откат не является полным откатом проекта.
5. Закройте напрямую запущенную игру. Для обычного запуска откройте игру через Steam, дождитесь лобби и нажмите **Inject trainer**. Лоадер не загружает готовые обновления по сети.

Для ручного отката после успешного обновления закройте игру и лоадер, сохраните текущий `CppSDK` под другим именем, затем переименуйте нужную папку `.auto_sdk_backup_<id>` в `CppSDK`. После этого пересоберите DLL с помощью `Build_Trainer_for_Loader.bat`.

## Ограничения и проверка

- Исходный лоадер и Dumper-7 взяты из второго архива пользователя. Подлинность, происхождение и безопасность бинарного `Dumper-7.dll` независимо не проверялись. SHA-256: `5b13729169c69a8feae5eb8813977619c3f54729f50362e453fbe68476fbadb9`.
- Windows-сборка, загрузка в процесс, поведение Dumper-7, откат и работа в игре не проверены в этой среде. Проверка была статической. Нужен тест на вашей машине; версии игры, Dumper-7 и SDK могут оказаться несовместимы.
- Новая сборка SDK не гарантирует, что игровые функции, сигнатуры или ручные смещения остались корректными. Пересборка может завершиться ошибкой или приложение может работать неправильно; не считать успешную сборку проверкой в игре.
- Вмешательство в игровой процесс может нарушать правила игры и привести к блокировке или сбою. Обход защит не реализовывался.
- Если файл версии игры не содержит `CL-<номер>`, лоадер не сможет определить сборку и остановится. Предусмотрено обнаружение только процесса `Hemingway-Win64-Shipping.exe`.
- `Build_Loader.bat` и `Build_Trainer_for_Loader.bat` рассчитаны на размещение в корне проекта, а `SmiteLoader.exe` — в его подпапке `dist`.
